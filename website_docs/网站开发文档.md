# 网站开发文档

以下是可直接放入项目根目录、供 Cline 在每次会话中加载的开发文档。它由两部分组成：**先给 Cline 的 `.clinerules/` 规则文件（约束 Cline 的行为）** ，再是 **完整的开发规格文档**。建议将规则文件放在 `.clinerules/` 下，将规格文档放在 `docs/SPEC.md`，Cline 启动任务时读取前者即可遵循技术约束，需要细节时再引用后者。

# 第一部分：`.clinerules/project.md`（直接给 Cline）

```markdown
# Project: Titanium CNC Parts — B2B RFQ Site

## Purpose
A statically generated, English-primary B2B website for an export-oriented
titanium CNC machining supply business. The site's only commercial goal is to
generate qualified drawing-based RFQ submissions and signal technical
credibility. It is NOT a product catalog, NOT an e-commerce site, and NOT a
factory showcase.

## Tech Stack (non-negotiable)
- Astro 5.x with `output: 'static'` — no SSR adapter. Do not add SSR.
- Tailwind CSS for styling. No component library.
- TypeScript strict mode. All `src/` files use TS unless a pure `.astro` file
  is sufficient.
- Content Collections (Astro 5 Content Layer API, `glob()` loader) for
  case studies and blog posts. Never hardcode repeated content into pages.
- Formspree (or Netlify Forms as deployment-dependent alternative). No custom
  backend, no serverless functions.
- `@astrojs/sitemap` for sitemap generation.

## Directory Conventions
src/
  components/     # reusable .astro components, PascalCase filenames
  layouts/        # BaseLayout.astro, PageLayout.astro
  pages/          # file-based routing; no logic beyond data fetching + layout
  content/        # content collections — case-studies/, blog/
  content.config.ts  # Astro 5 Content Layer schemas (note: NOT config.ts)
  lib/            # helpers: seo.ts, schema.ts, rfq.ts
  styles/         # global.css (Tailwind entry)
public/           # favicon, robots.txt, static PDFs (never expose factory names)

## Coding Rules
- Astro components: PascalCase filenames (`CapabilityTable.astro`).
- TS variables/functions: camelCase; types/interfaces: PascalCase;
  constants: UPPER_SNAKE_CASE.
- Every page must receive SEO props via `BaseLayout` — never hardcode
  `<title>` or meta tags inside page bodies.
- All RFQ CTAs must link to `/rfq/` unless the surrounding copy explicitly
  frames a different action.
- Never render supplier factory names, addresses, or contact details anywhere
  in the codebase or content. Use "qualified supplier network" consistently.
- Capability claims (tolerance, materials, max part size) must come from
  `src/lib/capabilities.ts` as a single source of truth. Pages and components
  import from there; never duplicate numbers in prose or tables.
- Do NOT invent case studies, certifications, or client names. Case study
  content must be clearly anonymized and marked as illustrative if not yet
  backed by a real transaction.

## SEO Constraints
- Every page needs a unique title, meta description, canonical URL, and
  Open Graph tags via `BaseLayout`.
- Inject JSON-LD via `<script type="application/ld+json" set:html={...}>`.
  Organization schema on home; BreadcrumbList on inner pages; Article schema
  on blog posts.
- Primary keyword patterns: `titanium CNC machining ±0.05 mm`,
  `custom titanium machined parts`, `3-axis 4-axis titanium machining`.
  Do not keyword-stuff; put capability numbers in HTML tables, not images.
- `robots.txt` in `public/` must reference the sitemap. Do not block
  legitimate crawlers.

## When Unsure
- Default to fewer pages, fewer claims, and more explicit "what we do not do"
  statements. Capability boundaries build trust; overclaiming destroys it.
- If a feature requires a backend (auth, dashboard, quote calculation),
  stop and ask — it is out of scope for this static build.
```


# 第二部分：开发规格文档（`docs/SPEC.md`）

## 1. 项目定位与设计原则

网站是 **“钛合金三轴/四轴 CNC 定制加工件的工程协调与供应入口”** ，不是产品目录。核心 KPI 是**合格图纸询盘数**和**从询盘到报价的转化率**，不是访问量。

三条设计原则贯穿全部页面：

**能力边界即信任。** 明确写出“不做什么”比罗列“能做什么”更能筛选买家。五轴复杂曲面、烧结滤芯、MMO 涂层、焊接钛篮不在范围内，必须在能力页和 RFQ 页显式声明。

**流程即产品。** 海外买家真正购买的不是“CNC 加工”，而是“图纸判断 → 双源报价 → 首件检验 → 尺寸报告 → 出口交付”这一套可控流程。网站的任务是把这套流程可视化。

**匿名案例优于虚构客户。** 没有真实成交案例时，用行业 + 零件族 + 材料 + 公差 + 批量 + 质检文件的匿名结构呈现，明确标注“illustrative example”，比伪造 Logo 更可信。

## 2. 技术栈与项目初始化

**初始化命令：**

```bash
npm create astro@latest titanium-rfq-site -- --template minimal --typescript strict
cd titanium-rfq-site
npx astro add tailwind sitemap
npm install @formspree/react   # 仅当需要 AJAX 提交时使用；基础方案用纯 HTML form
```

**`astro.config.mjs` 关键配置：**

```javascript
import { defineConfig } from 'astro/config';
import tailwind from '@astrojs/tailwind';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://yourdomain.com',   // 必须设置，否则 sitemap 和 canonical 失效
  output: 'static',
  integrations: [tailwind(), sitemap()],
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'zh'],
    routing: {
      prefixDefaultLocale: false,   // 英文主站不加 /en/ 前缀；中文走 /zh/
    },
  },
});
```

**关于 i18n 的决策：** 主站英文，中文作为辅助语言放在 `/zh/` 下。不做自动语言跳转；英文页面导航栏提供“中文”链接即可。中文版本不是逐句翻译，而是**面向中国供应链端/合作伙伴的简版说明**，页面数量控制在 3 页以内（首页简版、能力简版、联系页）。海外买家看到 `/zh/` 链接不应感到困惑，因此中文链接放在页脚而非主导航。

## 4. 内容模型（Content Collections）

**`src/content.config.ts`：**

```typescript
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';

const caseStudies = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/case-studies' }),
  schema: z.object({
    title: z.string(),
    industry: z.string(),
    partFamily: z.string(),
    material: z.string(),
    tolerance: z.string(),
    batchSize: z.string(),
    finishing: z.string().optional(),
    inspection: z.string(),
    leadTime: z.string(),
    repeatScenario: z.string().optional(),
    illustrative: z.boolean().default(true),  // 没有真实成交前必须为 true
    draft: z.boolean().default(false),
  }),
});

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.coerce.date(),
    updatedDate: z.coerce.date().optional(),
    draft: z.boolean().default(false),
  }),
});

export const collections = { caseStudies, blog };
```

**案例写作规范：** 正文按固定结构组织——**行业背景 → 零件类型与图纸特征 → 关键制造判断（为什么选三/四轴、0.05mm 如何保证）→ 质检与交付 → 重复采购场景**。不出现客户名、工厂名、具体价格。每篇案例末尾统一 CTA 指向 `/rfq/`。

**博客选题方向**（每篇对应一个搜索意图，底部 CTA 为 RFQ）：

- What ±0.05 mm tolerance means for titanium CNC machined parts
- 3-axis vs 4-axis CNC: what titanium parts each can handle
- How to prepare a drawing for a titanium CNC quotation
- Titanium surface finishing options for machined components
- Titanium replacement parts for industrial equipment: sourcing guide
- Why dual-source quoting matters for custom titanium parts

## 5. 单一能力数据源（`src/lib/capabilities.ts`）

所有页面中的能力数字必须从此文件导入，禁止在 prose 或表格中硬编码：

```typescript
export const CAPABILITIES = {
  processes: ['3-axis CNC', '4-axis CNC'],
  tolerance: '±0.05 mm (evaluated by feature and drawing)',
  materials: ['Grade 2', 'Grade 5 (Ti-6Al-4V)', 'Grade 7', 'Grade 9'],
  partFamilies: [
    'Flanges & fittings',
    'Brackets & mounts',
    'Housings & covers',
    'Shafts & bushings',
    'Replacement parts & spares',
  ],
  batchRange: 'Prototype to medium batch (typically 1–500 pcs)',
  finishing: ['As machined', 'Passivation', 'Bead blasting', 'Anodizing (if supplier-supported)'],
  inspection: ['First article inspection (FAI)', 'Dimensional report', 'Material certificate 3.1'],
  notOffered: [
    '5-axis complex surfaces',
    'Ultra-thin-wall or high-deformation parts',
    'Sintered titanium filter elements',
    'MMO-coated titanium anodes',
    'Welded titanium baskets / racks',
  ],
  supplyChain: 'Dual-source quotation from qualified suppliers in Baoji, China',
} as const;
```

`notOffered` 数组在能力页渲染为 **“We do not do”** 区块，在 RFQ 页渲染为复选框提示，在 `/quality/` 页作为 “scope boundary” 声明。

## 6. 页面规格

### 6.1 首页 `/`

首屏必须让工程师/采购在 5 秒内判断“是否值得上传图纸”：

```
H1: Custom Titanium CNC Machined Parts
Subline: 3-axis / 4-axis · ±0.05 mm tolerance · Drawing-based · Small to medium batches
Primary CTA: Upload Drawing / Request Quote → /rfq/
Secondary CTA: Check Machining Capability → /capabilities/
```

首屏下方依次：

**信任条**（3—4 个短语）：Dual-source quotation · FAI & dimensional report · English engineering review · Export documentation

**能力快照表**（从 `CAPABILITIES` 渲染）：Process、Tolerance、Materials、Batch range、Inspection

**零件族网格**：4 张卡片（法兰/接头、支架/安装座、壳体/盖板、设备备件），每张卡片底部链接到对应 `/parts/` 页面。

**流程条**（`ProcessFlow` 组件，5 步）：Upload drawing → Engineering review → Dual-source quote → Production & inspection → Export delivery.

**匿名案例预览**：拉取 2 条 `caseStudies`，展示 industry + partFamily + tolerance + inspection，链接到 `/case-studies/`。

**RFQ 横幅**：一句话 + 按钮 “Send your drawing for review”。

### 6.2 能力页 `/capabilities/`

这是全站最重要的筛选页。结构：

1. **Capability table**：Process、Tolerance、Materials、Max part size（留占位符，供应商数据到位后填入）、Batch range、Finishing、Inspection。
2. **Part families**：从 `CAPABILITIES` 渲染为定义列表，每条一句话说明典型特征。
3. **What we do not do**：渲染 `notOffered` 数组，每条配一句简短原因（例如“5-axis complex surfaces — out of current supplier scope”）。
4. **Supply chain note**：一段说明“dual-source quotation from qualified suppliers”的流程价值，不暴露工厂名。
5. **CTA**： “Your part is not listed? Still send the drawing — we will tell you honestly if it is a fit.”

### 6.3 零件族页 `/parts/flanges-fittings/` 等

每个页面结构统一，不写成产品目录：

- **H1**：`Titanium Flanges & Fittings — Custom Machined to Drawing`
- **典型图纸特征**：2—3 句描述常见几何（如“raised-face flanges, threaded fittings, stepped diameters”）
- **适用材料与公差**：从 `CAPABILITIES` 引用
- **常见后处理**：仅列供应商实际支持的
- **质检文件**：FAI + dimensional report + material cert
- **重复采购场景**：1—2 句（OEM 配套、备件替换、设备维修）
- **匿名案例链接**（如果有匹配的 case study）
- **CTA**：Upload Drawing

**不在零件族页放价格、库存、SKU 编号，也不放“标准件”的尺寸表**——那会把定制件生意拉回价格透明的标准品交易。

### 6.4 质量页 `/quality/`

轻资产模式最需要的信任页面。内容：

**Inspection workflow**：从“图纸接收时定义关键尺寸”到“首件检验 → 尺寸报告 → 表面处理确认 → 包装前终检”的 4—5 步流程，用简洁的编号列表呈现。

**Document outputs**：FAI report、dimensional report、material certificate 3.1、finishing record、packing photos（按供应商实际能力勾选）。

**Dual-source quality logic**：一段话解释“同一图纸向两家合格供应商询价，比较工艺方案和质检计划后再下单”——这既是价格控制手段，也是质量冗余。

**Scope boundary**：再次列出 `notOffered`，放在质量页底部，强化“只做能力范围内的事”。

### 6.5 合作流程页 `/how-it-works/`

按步骤呈现 **客户需要提供什么 / 你负责什么 / 输出什么文件** 的三列表格。5 步：

| Step | Customer provides | We do | Output |
|---|---|---|---|
| 1. Upload drawing | 2D PDF / 3D STEP, material, qty, tolerance, finishing | Initial feasibility scan | Acknowledgement within 1 business day |
| 2. Engineering review | Clarifications if needed | DFM check, scope confirmation | Go / no-go + questions |
| 3. Dual-source quotation | Target delivery | Two supplier quotes compared | Consolidated quotation with lead time |
| 4. Production & inspection | PO confirmation | Coordination, FAI, dimensional report | Inspection documents before shipment |
| 5. Export & repeat | Shipping terms | Export docs, after-sales | Delivery + archived drawing/order record |

页面末尾明确：**“We do not forward your drawing to suppliers without a mutual NDA in place.”**

### 6.6 RFQ 页 `/rfq/`

全站转化核心。表单字段：

- Name / Company / Email / Country（必填）
- **Drawing upload**（文件输入，接受 PDF/STEP/DWG/IGES；如 Formspree 计划不支持大文件，改为“上传后我们回复安全链接”的文案，但表单必须保留文件入口）
- Material grade（下拉，选项从 `CAPABILITIES.materials` 生成，含“Not sure”）
- Quantity（数字）
- Tolerance requirement（文本，预填 `±0.05 mm` 作为提示，但允许客户覆盖）
- Surface finishing（下拉，选项从 `CAPABILITIES.finishing` 生成，含“Not specified”）
- Application / industry（文本）
- Target delivery date（日期）
- **NDA request**（复选框）
- Message（文本域）

表单上方用一段 3 行以内的文案说明：

> Files are reviewed internally before any supplier sees them.  
> We will confirm feasibility and scope before quoting.  
> Complex parts outside 3/4-axis scope will be declined honestly.

**提交行为**：使用 Formspree 的 HTML `action`（例如 `https://formspree.io/f/xxxx`），`method="POST"`。成功后重定向到 `/thank-you/`。如果后续需要 AJAX 体验，再用 `@formspree/react` 或原生 fetch 拦截，但 MVP 不做。

**`/thank-you/` 页面**：确认“已收到，1 个工作日内回复”，并列出客户接下来会经历什么（engineering review → quotation），附带返回 `/capabilities/` 和 `/how-it-works/` 的链接。设置 `noindex`。

### 6.7 案例页 `/case-studies/`

索引页按行业或零件族分组卡片。卡片显示：industry badge、partFamily、tolerance、inspection。如果有 `illustrative: true`，显示 “Illustrative example” 小标签。

详情页 `/case-studies/[slug]/` 用 `PageLayout`，顶部显示元信息表（industry / part family / material / tolerance / batch / finishing / inspection / lead time），正文按案例规范结构展开，底部 CTA 为 RFQ。

### 6.8 关于页 `/about/`

不写“我们是一家位于宝鸡的贸易公司”。写：

> We coordinate a qualified network of titanium CNC machining suppliers in Baoji, China. We control engineering review, dual-source quotation, inspection coordination, export delivery, and the customer relationship. We do not own machines — we own the process between your drawing and the delivered part.

然后列出你控制的四件事（demand intake、technical review、supply chain coordination、customer & transaction ownership），用简洁的图标 + 短句呈现。

### 6.9 中文简版 `/zh/`

三页：`/zh/`（首页简版，说明“面向中国供应链合作与中文沟通”）、`/zh/capabilities/`（能力表中文版）、`/zh/contact/`（中文联系表单，字段精简为姓名、公司、邮箱、留言）。不做完整翻译，不在英文页面放语言切换浮层；页脚底部放一个“中文”文字链接。

## 7. SEO 与结构化数据

**`BaseLayout.astro` 接收的 props**：`title`、`description`、`canonical`（自动从 `Astro.url` 构造）、`ogImage`（默认 `/og-default.jpg`）、`noindex`（布尔，默认 false）、`jsonLd`（对象或对象数组，可选）。

**JSON-LD 策略**：

- 首页：`Organization` + `WebSite`（`name`、`url`、`description`、`contactPoint` 用 RFQ 邮箱）。
- 能力页 / 零件族页：`BreadcrumbList` + `Service`（`serviceType: "Titanium CNC machining"`，`areaServed: "Worldwide"`，`provider` 指向 Organization）。
- 博客文章：`Article`（`headline`、`datePublished`、`dateModified`、`author` 用 Organization）。
- 案例详情：`Article`，`about` 填零件族。

**关键词落地原则**（参考制造业 SEO 实践）：工程师搜索的是 **工艺 + 材料 + 公差 + 行业** 的组合，而不是“精密解决方案”。每篇博客和零件族页围绕一个具体组合组织内容（例如 `titanium CNC machining ±0.05 mm`、`custom titanium flanges machined to drawing`）。能力数字放在 HTML 表格中，不放图片。

**`public/robots.txt`**：

```
User-agent: *
Allow: /
Disallow: /thank-you/

Sitemap: https://yourdomain.com/sitemap-index.xml
```

## 8. 表单与图纸上传的边界说明

静态站点无法自行接收文件。Formspree 的免费/低阶计划对文件大小和附件类型有限制。开发文档中需要 Cline 实现的行为是：**RFQ 表单保留 `<input type="file">`，但不在前端做上传进度或 AJAX 提交**。如果 Formspree 计划不支持该文件类型/大小，在 `/rfq/` 页面用一行提示替代：

> If the drawing exceeds the upload limit, submit the form without the file and we will reply with a secure upload link.

这样既不假装有后端能力，也不阻断 RFQ 转化。**不要**为此引入 Astro API route 或 SSR 适配器。

## 9. 部署

**目标**：Cloudflare Pages 或 Netlify，纯静态 `dist/` 输出，无适配器。

Cloudflare Pages 构建命令 `npm run build`，输出目录 `dist`。Netlify 同理；如果选择 Netlify Forms 替代 Formspree，在 `<form>` 上加 `data-netlify="true"` 和隐藏的 `form-name`，但**二选一，不要同时配两套**。

`astro.config.mjs` 中的 `site` 必须设置为最终生产域名，否则 sitemap 和 canonical 会出错。

## 10. MVP 实施顺序

**第一周**：`capabilities.ts` → `BaseLayout` + `SEOHead` + `Header/Footer` → `/capabilities/` → `/rfq/` + `/thank-you/` → `/quality/` → 首页。五页即可上线。

**第二周**：`/how-it-works/` → `/about/` → 2 个零件族页（flanges-fittings、replacement-spares） → 2 篇匿名案例 → 3 篇博客。

**第三周**：剩余零件族页、行业页、`/zh/` 三页、补全 JSON-LD、sitemap 验证、表单生产环境测试（Netlify/Formspree 必须在部署后测试，本地 `astro dev` 不触发真实提交）。

**验收标准**：Cline 完成 MVP 后，应能运行 `npm run build` 无错误，`dist/` 包含 `sitemap-index.xml`，`/rfq/` 在生产域名下提交一次测试文件并收到 Formspree 确认邮件（或 Netlify 表单记录），`/capabilities/` 中 “We do not do” 区块渲染正常，所有页面 `<title>` 唯一且 canonical 指向正确。
